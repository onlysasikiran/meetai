# Research and dependencies

## Benchmark material

| Source | Phase 1 use | Upstream terms |
| --- | --- | --- |
| ELITR-Bench by Thonet, Besacier and Rozen | Human English questions and answers. Load the QA development archive using the authors' published extraction procedure. | QA layer CC BY 4.0. The authors password-protect the archive to limit training contamination. [Repository and data license](https://github.com/utter-project/ELITR-Bench) · [COLING paper](https://aclanthology.org/2025.coling-main.28/) |
| ELITR Minuting Corpus by Nedoluzhko et al. | Original manual meeting transcripts for those QA IDs. | Separate CC BY-NC-SA 4.0 corpus. [Publisher record](https://hdl.handle.net/11234/1-4692) |
| QMSum by Zhong et al. | Specific-query summaries and official turn spans. | Yale repository declares MIT. Consult the originating meeting corpora for their own data terms. [Repository](https://github.com/Yale-LILY/QMSum) · [Paper](https://aclanthology.org/2021.naacl-main.472/) |
| MeetingBank by Hu et al. | Validation agenda segments for ingestion, memory and a summary smoke test. | Dataset card declares CC BY-NC-SA 4.0. [Dataset card](https://huggingface.co/datasets/huuuyeah/meetingbank) · [Project](https://meetingbank.github.io/) |
| MeetAI-Stress | Four reproducible scenario instances with distant links, owner and date changes, nearby names, distracting instructions and unanswerable questions. | Generated by [the project](bench/stress.py). Ground truth is recorded during scenario construction. |

The project downloads upstream assets by SHA-256. The public repository contains retrieval traces, annotations and scores. Model binaries, third-party source transcripts, upstream question text and verbatim real-model outputs are reconstructed locally. [Pinned URLs and hashes](configs/assets.json)

## Models and execution

| Component | Source and terms |
| --- | --- |
| BGE-small-en-v1.5 | MIT upstream. A quantized Xenova export produces 384-dimensional normalized CLS vectors. The query instruction is applied only to queries. [Model card](https://huggingface.co/BAAI/bge-small-en-v1.5) · [ONNX export](https://huggingface.co/Xenova/bge-small-en-v1.5) |
| MS MARCO MiniLM L6 v2 | Apache 2.0 upstream. A separate quantized Xenova cross-encoder scores each question/passage pair. [Model card](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2) · [ONNX export](https://huggingface.co/Xenova/ms-marco-MiniLM-L-6-v2) |
| Qwen3-4B Q4_K_M | Official Apache 2.0 GGUF. llama.cpp uses the embedded tokenizer, greedy decoding, CPU kernels and non-thinking chat format. [Model and license](https://huggingface.co/Qwen/Qwen3-4B-GGUF) |
| Runtime | llama-cpp-python and ONNX Runtime are MIT, Hugging Face Tokenizers is Apache 2.0, NumPy and pypdf use BSD licenses, pytest is MIT. SQLite and platform resource measurement are supplied by Python. Exact installed versions are pinned in [requirements.lock](requirements.lock). [llama-cpp-python](https://github.com/abetlen/llama-cpp-python) · [ONNX Runtime](https://github.com/microsoft/onnxruntime) · [Tokenizers](https://github.com/huggingface/tokenizers) · [pypdf](https://github.com/py-pdf/pypdf) |

## Architecture references checked

| Reference | Project decision |
| --- | --- |
| Ilya Rice, RAG Challenge 2 | Included conventional parent retrieval as an option for the baseline. Its competition pipeline highlights vector search with parent retrieval and reranking. [MIT repository](https://github.com/IlyaRice/RAG-Challenge-2) |
| Ilya Rice, Enterprise RAG Challenge 3 | The runtime builds named context blocks. This informs Phase 2 selective expansion. The baseline has its own local retrieval and generation path. [MIT implementation](https://github.com/IlyaRice/Enterprise-RAG-Challenge-3-AI-Agents/blob/main/benchmarks/erc3/runtime/context.py) |
| LongRefiner and VikingRAG | Candidates for organizing and refining context in Phase 2. Their published numbers are separate experiments. [LongRefiner](https://aclanthology.org/2025.acl-long.176/) · [VikingRAG](https://arxiv.org/abs/2609.11390) |
| Geometric Gain Graph and EfficientRAG | Lightweight linking and targeted additional retrieval are candidate approaches for distant evidence. [Graph paper](https://arxiv.org/abs/2609.19622) · [EfficientRAG](https://aclanthology.org/2024.emnlp-main.199/) |
| Zep and LLMLingua-2 | References for evolving facts and compression. Each addition requires a comparison with the frozen baseline. [Zep](https://arxiv.org/abs/2501.13956) · [LLMLingua-2](https://arxiv.org/abs/2403.12968) |
